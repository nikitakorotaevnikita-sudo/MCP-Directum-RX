# Навык «Excel-выгрузка»

Скрипт `scripts/build_xlsx.py` собирает .xlsx из JSON-спецификации. Ты готовишь спецификацию из реальных
данных тулов и вызываешь скрипт; стили, типы ячеек, формулы итогов и защита от формул делаются автоматически.

## Когда использовать

- «Выгрузи в Excel», «сделай xlsx», «таблицу, чтобы отфильтровать/отсортировать», «дай список для обработки».
- Много строк (до 50 000 на лист), несколько наборов данных — по листу на каждый.
- Нужен документ для чтения/печати с выводами — навык `pdf-report`.

## Как вызвать

```bash
python scripts/build_xlsx.py spec.json /путь/к/выгрузка.xlsx
# или спецификация через stdin:
cat spec.json | python scripts/build_xlsx.py - /путь/к/выгрузка.xlsx
```

Из Python: `from build_xlsx import build; path = build(spec_dict, "выгрузка.xlsx")` (при ошибке — `SpecError`).

Зависимость: `pip install -r requirements.txt` (openpyxl). Сеть не нужна.

| Код выхода | Значение | Что делать |
|---|---|---|
| 0 | Успех, в stdout — абсолютный путь к файлу | Отдай файл пользователю |
| 2 | Ошибка спецификации (или пути вывода), в stderr — список «поле: что не так» | **Исправь спецификацию по сообщению и вызови ещё раз.** Не подгоняй данные |
| 1 | Непредвиденная ошибка (нет прав на запись и т. п.) | Сообщи пользователю текст ошибки |

Пример сообщения при коде 2:
```
Ошибка спецификации:
- sheets[0].rows[5][2]: ожидалось число для колонки типа integer, получено 'пять'
- sheets[0].totals.columns[0]: колонка 'days' не найдена; укажите key, заголовок или индекс (с 0). Колонки: 'subject', 'deadline', 'days_overdue'
```

Файл пишется атомарно (временный файл в той же папке → переименование); недописанный .xlsx не остаётся.
Папки создаются автоматически. Путь вывода обязан оканчиваться на `.xlsx`.

## Формат спецификации

Схема (комментарии `//` только для пояснения — в настоящем JSON их быть не должно):

```jsonc
{
  "properties": {"title": "Название файла", "author": "Кто подготовил"},   // необязательно
  "sheets": [                                                              // обязательно, 1–50 листов
    {
      "name": "Поручения",               // обязательно; очищается и укорачивается автоматически (см. ниже)
      "title": "Строка над таблицей",    // необязательно, крупный жирный текст в строке 1
      "columns": [                       // обязательно
        {"title": "Тема", "key": "subject", "type": "text", "width": 50, "format": null}
      ],
      "rows": [ ... ],                   // обязательно: списки значений или объекты по key
      "totals": {"label": "Итого", "columns": ["days_overdue"], "func": "sum"},          // необязательно
      "highlight": [{"column": "days_overdue", "op": ">", "value": 30, "color": "red", "row": true}]  // необязательно
    }
  ]
}
```

Неизвестные поля — ошибка (так ловятся опечатки).

### Колонки

| Поле | Описание |
|---|---|
| `title` | Заголовок колонки (обязательно). Можно вместо объекта написать просто строку — тогда тип `text` |
| `key` | Имя поля, если `rows` — объекты. Уникально в пределах листа |
| `type` | `text` (по умолчанию), `number`, `integer`, `percent`, `date`, `datetime`, `url`, `bool` |
| `width` | Ширина в символах 1–255. Без неё — автоширина по содержимому, от 10 до 60 |
| `format` | Числовой формат Excel, например `"0.000"`, `"# ##0 ₽"`. По умолчанию: number `#,##0.00`, integer `#,##0`, percent `0.0%`, date `DD.MM.YYYY`, datetime `DD.MM.YYYY HH:MM` |

### Типы и значения

| type | Что принимается | Что в Excel |
|---|---|---|
| `text` | строка, число, true/false | текст. ISO-дата в тексте → «ДД.ММ.ГГГГ»; `[текст](https://…)` → гиперссылка (одна на ячейку — первая) |
| `number` | число или строка `"1 234,5"` | число |
| `integer` | целое (или `"12"`, `12.0`) | целое число; дробное — ошибка |
| `percent` | **доля**: `0.876` → 87,6 %. Строка с `%`: `"87.6%"` → 87,6 % | число с форматом процента |
| `date` | `"2026-09-28"`, `"2026-09-28T00:00:00+04:00"`, `"28.09.2026"` | настоящая дата Excel (время отбрасывается) |
| `datetime` | те же форматы, `"28.09.2026 14:05"` | дата-время Excel (время как в строке, пояс не пересчитывается) |
| `url` | `"https://…"`, `{"text": "Открыть", "url": "https://…"}` или `"[Открыть](https://…)"` | гиперссылка (атрибут ячейки, не формула) |
| `bool` | `true`/`false`, `"да"`/`"нет"`, `"true"`/`"false"`, `1`/`0` | логическое значение |

- `null` или пустая строка → пустая ячейка в любой колонке.
- `{"text", "url"}` допустим в любой колонке — ячейка станет гиперссылкой.
- Разрешены только ссылки `http://` и `https://`; `javascript:`, `file:` и пр. — ошибка (код 2).
- **Защита от формул:** текст, начинающийся с `=`, `+`, `-`, `@`, табуляции или перевода строки, записывается
  как обычный текст (с префиксом-апострофом Excel), а не как формула. Формулы в файле — только итоги, которые делает скрипт.
- Управляющие символы, недопустимые в XML, удаляются из текста.

### Строки

- Списки: `["Тема", "2026-09-28", 5]` — ровно столько значений, сколько колонок.
- Объекты: `{"subject": "Тема", "deadline": "2026-09-28", "days_overdue": 5, "id": 7}` — значения берутся по `key`
  колонок, **лишние поля игнорируются**, отсутствующие → пустая ячейка. Поэтому элементы `items` из ответа тула
  можно передавать как есть. Для строк-объектов у всех колонок должен быть `key`.
- Пустой список строк → строка «Нет данных».

### Итоги (`totals`)

`{"label": "Итого", "columns": [ключ | заголовок | индекс с 0, ...], "func": "sum" | "count" | "avg"}`

- Строка итогов идёт сразу под данными и содержит **настоящие формулы Excel**: `SUM`, `COUNTA` (число непустых),
  `AVERAGE` (в `IFERROR`, чтобы не было `#ДЕЛ/0!`) по диапазону данных.
- `sum`/`avg` — только для числовых колонок (`number`, `integer`, `percent`); `count` — для любых.
- `label` (по умолчанию «Итого») ставится в первую колонку, не занятую итогами.
- Одна функция на лист. Нужны разные — сделай отдельные колонки/листы или посчитай в PDF-сводке.

### Подсветка (`highlight`)

`{"column": ключ | заголовок | индекс, "op": ">" | "<" | ">=" | "<=" | "==" | "!=", "value": …, "color": "red", "row": false}`

- Реализована **условным форматированием** Excel (правило живёт в файле: работает после сортировки/фильтра
  и пересчитывается при правке значения). Пустые ячейки не подсвечиваются.
- `value`: число для числовых колонок (для percent — доля или `"30%"`), дата `ГГГГ-ММ-ДД` для дат,
  `true/false` для bool, строка для текстовых (только `==`/`!=`, без учёта регистра).
- `color`: `#RRGGBB` или `red`, `orange`, `yellow`, `green`, `blue`, `gray`. По умолчанию `yellow`.
- `row: true` — подсвечивать всю строку, иначе только ячейку.

### Имена листов

Excel требует: ≤31 символ, без `[ ] : * ? / \`, не начинается и не заканчивается апострофом, уникально.
Скрипт сам заменяет запрещённые символы пробелом, обрезает до 31 символа, пустое имя → «ЛистN»,
совпадающие (без учёта регистра) получают суффикс ` (2)`, ` (3)`…

### Оформление (автоматически)

Жирная шапка с заливкой и переносом, закрепление под шапкой, автофильтр на диапазон данных, сетка,
перенос текста в длинных ячейках, автоширина колонок 10–60 символов (если не задан `width`).

## Как превратить результаты mcpOGV в спецификацию

### Поручения сотрудника (`admin_list_employee_action_items`)

Ответ: `{"items": [{"id", "subject", "deadline", "days_overdue", "author", "performer", "url", "status", ...}], "total", "returned", "truncated", "employee": {"name"}}`.

Передай `items` как `rows` (объекты) и опиши колонки ключами:

| Колонка | key | type |
|---|---|---|
| Тема | `subject` | text (width 50) |
| Срок | `deadline` | date |
| Дней просрочки | `days_overdue` | integer |
| Кто выдал | `author` (для `direction="outgoing"` — «Исполнитель», `performer`) | text |
| Ссылка | `url` | url |

Имя листа — «Просроченные» / «Входящие» / «Исходящие»; `title` — ФИО сотрудника и дата. Если `truncated: true` —
запроси больше записей (увеличь `limit`) или напиши в `title`: «показано N из total».

### Обращения граждан по тематикам (`get_citizen_requests_analytics`)

Лист «Тематики»: `rows` = `groups` (объекты), колонки `code` (Код), `name` (Тематика / Раздел / Тема — по `level_label`),
`requests` (Обращений, integer), `questions` (Вопросов, integer); `totals` — `sum` по обоим.
Лист «Итоги рассмотрения»: `rows` = `review_results`, колонки `label` (Итог), `count` (Количество, integer).
В `title` — период `date_from`–`date_to` и «всего обращений: requests_total». Не путай обращения и вопросы.

## Правила

1. **Никогда не выдумывай данные.** Все значения — только из ответов тулов. Нет значения — `null`.
2. **Сохраняй ссылки** на карточки RX — колонка типа `url`.
3. Даты передавай как пришли (ISO) и задавай колонке `type: "date"` — в Excel будет настоящая дата ДД.ММ.ГГГГ,
   по которой можно сортировать и фильтровать.
4. Числа — как числа (`integer`/`number`), не строками с единицами измерения: «41», а не «41 дн.».
5. **Персональные данные граждан** (ФИО заявителя, адрес, телефон, e-mail, текст обращения) не выгружай,
   если пользователь явно не попросил и это не нужно для задачи.
6. Итоги — через `totals` (формулы), а не посчитанными вручную числами.
7. После успешного вызова отдай путь к файлу и кратко скажи, что в нём (листы, число строк).

## Лимиты

| Что | Максимум |
|---|---|
| Листов | 50 |
| Колонок на листе | 100 |
| Строк на листе | 50 000 (≈30 с сборки) |
| Ячеек во всём файле | 1 000 000 |
| Правил подсветки на листе | 20 |
| Символов в ячейке | 32 000 (предел Excel — 32 767) |
| Символов в заголовке/подписи | 500 |
| Длина ссылки | 2 000 |
| Размер спецификации | 50 МБ |
