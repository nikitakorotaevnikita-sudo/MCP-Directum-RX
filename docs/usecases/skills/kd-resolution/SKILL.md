# Навык «Проект резолюции»

Ты помогаешь помощнику руководителя или делопроизводителю подготовить проект резолюции по новому входящему документу
так, как обычно расписывает этот руководитель. Основа — история его поручений в RX: кому он поручал похожие темы,
с кем в паре, ставил ли на контроль и на какой срок. Решение принимает руководитель; ты готовишь проект с
обоснованием.

## Данные

1. **Автор резолюции** — ФИО руководителя. Если mcpOGV работает под служебной учёткой (`get_current_user` →
   `service_account=true`), «me» не подходит: спроси ФИО.
2. **Входящий документ** — `find_documents` или id от пользователя → `get_document` (название, корреспондент),
   `get_document_text` (текст). Нет текста (скан) — скажи об этом; прогноз по одному названию будет грубее.
   Прислан PDF — навык `pdf-read`.
3. **История** — `get_resolution_history(author=ФИО, limit=1000)`; по умолчанию за 2 года. Ответ сохрани в файл как
   есть. `truncated: true` — история неполная, скрипт это отметит.

## Скрипт

```bash
python scripts/suggest_resolution.py входящее.txt --history история.json \
    --title "Вх. письмо … «О …»" --today 2026-09-30 --format md
```

Что делает:
- **похожие поручения** — сопоставление по основам слов (TF-IDF) с названием документа-основания, темой и текстом
  прошлых поручений; общие служебные слова («прошу», «подготовить», «информацию»…) не учитываются; давние поручения
  весят меньше (половина веса за год);
- **исполнитель** — кому автор поручал похожее (доля по весу, число поручений, последняя дата, примеры);
- **соисполнители** — кто был соисполнителем или исполнителем пунктов в похожих поручениях этого исполнителя
  (не меньше 2 раз и 30 % случаев);
- **контроль** — по порядку: прямое «на контроль» в тексте → документ вышестоящего или федерального органа со сроком
  или докладом → привычка автора по похожим (если их 5 и больше: на контроль, если так было в половине и больше
  случаев) → признаки текста (установленный срок и требование доклада). Контролёр — кто обычно контролировал
  похожие;
- **срок** — установленный документом срок минус 3 рабочих дня на подготовку ответа; иначе — типичный срок похожих
  поручений автора; иначе — «укажите сами»;
- **черновик резолюции** — исполнители, формулировка из самого похожего поручения этого исполнителя (без служебного
  «Вы являетесь исполнителем. п.1»), срок, контроль;
- **уверенность** — высокая / средняя / низкая. При низкой исполнителя не предлагает, а показывает частых исполнителей
  автора.

Коды выхода: 0 / 2 (плохой вход — исправь и повтори) / 1.

## Как излагать

```
Проект резолюции по [Вх. письмо № 088-ВХ](url) — уверенность высокая:

Иванов И. И. (отв.), Смирнов А. В.
Прошу представить информацию.
Срок — 15.10.2026.
На контроль (контролёр — Орлова Е. В.).

Почему так:
- Иванов И. И. — 3 из 3 похожих поручений автора (последнее 05.09.2026: [№ 109](url)), Смирнов А. В. — соисполнитель в 2 из них.
- Контроль: письмо Аппарата Правительства со сроком 20.10.2026; похожие поручения автора на контроле — 3 из 3.
- Срок: документ требует до 20.10.2026, минус 3 рабочих дня на подготовку ответа.
```

1. Черновик резолюции — дословно из `resolution_draft`, в блоке, чтобы его можно было скопировать в RX.
2. «Почему так» — 2–4 пункта: исполнитель (доля и примеры со ссылками), соисполнители, контроль (причины из
   `control.reasons`), срок (`deadline.basis`).
3. Альтернативы — второй кандидат, если его доля заметная (от 25 %).
4. Уверенность средняя или низкая — прямо скажи и предложи руководителю выбрать самому.
5. Как оформить в RX: помощник — «Добавить поручение» в задании на рассмотрение (проект резолюции); руководитель —
   «Создать поручение» или текст резолюции; контроль — флажок «На контроле» и контролёр в поручении.

## Оформить через ассистента (если включены тулы записи)

Только по явной просьбе и после подтверждения пользователя (два шага: предпросмотр → «да» → `confirm_token`).

| Что хочет пользователь | Тул | Что передать |
|---|---|---|
| Сразу выдать резолюцию | `create_action_items` | `document_id` входящего, `on_behalf_of` = ФИО автора резолюции, `items`: ответственный и каждый соисполнитель — отдельным поручением (`assignee`, `deadline` из `deadline.proposed`, `text` из черновика), у поручения с контролем — `under_control: true` и `supervisor` из `control.supervisor` |
| Отдать руководителю на рассмотрение с проектом | `send_document_for_review` | `document_id`, `addressee` = руководитель, `on_behalf_of` = помощник, `text` — черновик резолюции целиком |
| Одно поручение | `create_action_item` | как один элемент `items` выше; соисполнитель — `co_assignee` |

- Предпросмотр покажи списком: кому, что, срок, контроль; спроси «Выдать?».
- После создания — ссылки и итог по каждому поручению (`created`, `started`, `failed`, `warnings`). Если поручение не
  запущено («Выдал» не проставился) — скажи, что оно в черновиках, и как запустить в RX.
- Исполнителей с уверенностью «низкая» сам не выдавай — сначала пусть пользователь выберет.

## Правила

- Не предлагай исполнителя, которого нет в истории: при низкой уверенности — только частые исполнители автора.
- Исполнитель мог уволиться, сменить участок или быть в отпуске — предупреждай, если последнее похожее поручение
  старше года.
- Формулировку поручения не выдумывай: из похожего поручения или нейтральная «Прошу рассмотреть и подготовить
  предложения».
- Не выводи ФИО граждан из обращений в обосновании; ссылайся на номер поручения.
- Ты готовишь проект. Создать поручения можно только тулами записи (если они включены) и только после «да»
  пользователя; без них — объясни, как оформить в RX.
