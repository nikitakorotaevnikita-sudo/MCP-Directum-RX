# Навык «Презентация PowerPoint: пять слайдов»

Скрипт `scripts/build_pptx.py` собирает готовую презентацию `.pptx` из JSON-спецификации: ровно пять слайдов в
едином аккуратном стиле, без пустых слайдов и без «воды». Ты не пишешь код вёрстки — ты собираешь факты
инструментами, раскладываешь их по слайдам в спецификацию и вызываешь скрипт.

## Структура — ровно 5 слайдов

| № | Слайд | Что на нём |
|---|---|---|
| 1 | Титульный | Строится сам из `title`, `subtitle`, `author`, `date` |
| 2 | Содержание / ключевые тезисы | 3–5 коротких пунктов о том, что будет дальше |
| 3 | Суть / проблема | Главная идея или проблема: 3–5 пунктов + один показатель (`metric`), если есть данные |
| 4 | Решение / данные | Что предложено и ключевые цифры: таблица или список из 3–5 пунктов |
| 5 | Заключение / что дальше | 2–3 вывода + 1–3 следующих шага: кто, что, к какому сроку |

Слайды не дублируют друг друга: у каждого своя роль. В спецификации — заголовок и ровно 4 слайда в `slides`
(слайды 2–5); другое количество скрипт не примет.

## Данные — только из инструментов

- Номера, даты, ФИО, цифры и ссылки — только из ответов инструментов в этом диалоге (Directum RX через mcpOGV,
  ГАРАНТ, поиск) или из того, что дал пользователь. Ничего не выдумывай.
- Тема про поручения, обращения граждан, НПА, дисциплину — **сначала собери данные инструментами**, потом слайды.
- Данных для слайда нет — сформулируй его нейтрально и поставь `"pending": true`: на слайде появится пометка
  «данные уточняются».
- Ссылки на карточки RX (поле `url` из ответов инструментов) можно давать в пунктах и ячейках таблицы.

## Как выполнять

1. **Понять запрос:** тема, для кого, есть ли данные. Если тема связана с RX — собери данные инструментами.
2. **Разложить по слайдам** по структуре выше: короткие фразы, без канцелярита, не больше 5 пунктов на слайде.
3. **Собрать спецификацию** (формат ниже) и вызвать скрипт.
4. **Код 2** — исправь спецификацию по сообщению об ошибке и вызови ещё раз (не меняй данные «на глаз»).
5. **Отчитаться:** имя файла, что на каждом из 5 слайдов (одной строкой), что можно поменять. Код пользователю не
   показывай.

## Как вызвать

```bash
python scripts/build_pptx.py spec.json /mnt/data/название-темы.pptx
# или спецификация через stdin:
cat spec.json | python scripts/build_pptx.py - /mnt/data/презентация.pptx
```

Из Python: `from build_pptx import build; path = build(spec_dict, "презентация.pptx")` (при ошибке — `SpecError`).
Зависимость: `pip install -r requirements.txt` (python-pptx). Сеть не нужна. Сохраняй файл в `/mnt/data/` — так он
доставляется пользователю; имя — по теме.

| Код выхода | Значение | Что делать |
|---|---|---|
| 0 | Успех, в stdout — абсолютный путь к файлу | Отдай файл пользователю |
| 2 | Ошибка спецификации, в stderr — список «поле: что не так» | Исправь спецификацию по сообщению и вызови ещё раз |
| 1 | Непредвиденная ошибка | Сообщи пользователю текст ошибки |

Файл пишется атомарно: недописанная презентация не остаётся; папки создаются сами; путь обязан оканчиваться на
`.pptx`.

## Формат спецификации

Комментарии `//` — только для пояснения, в настоящем JSON их быть не должно. Рабочий пример —
`examples/example_spec.json`.

```jsonc
{
  "title": "Исполнительская дисциплина: итоги октября",   // обязательно, до 120 символов
  "subtitle": "Поручения на контроле и просрочки",         // необязательно
  "author": "Отдел контроля исполнения",                   // необязательно: автор / подразделение
  "date": "2026-11-16",                                    // необязательно, выводится как 16.11.2026
  "slides": [                                              // ровно 4: слайды 2–5
    {
      "title": "Суть и проблема",                          // обязательно, до 90 символов
      "bullets": [                                         // до 5 пунктов; строка или объект
        "Просроченных поручений стало больше",
        {"text": "Основная доля — по обращениям", "level": 1},          // подпункт, до 3 у пункта
        {"text": "Карточка поручения", "url": "https://…/card/1072"}    // ссылка http/https
      ],
      "metric": {"value": "45", "label": "поручений просрочено"},       // крупный показатель справа
      "table": {                                           // до 6 колонок и 8 строк; с таблицей — до 3 пунктов
        "columns": ["Подразделение", "Просрочено"],
        "rows": [["Отдел ЖКХ", 12], ["Отдел дорог", {"text": "Открыть", "url": "https://…"}]]
      },
      "pending": false,                                    // true — пометка «данные уточняются»
      "notes": "Заметки докладчика"                        // необязательно, видны в режиме докладчика
    }
  ]
}
```

На слайде должно быть хотя бы одно из: `bullets`, `table`, `metric`. Даты ГГГГ-ММ-ДД в ячейках выводятся как
ДД.ММ.ГГГГ. Длинный список (больше 8 строк) в презентацию не помещай — оставь главное, полный список дай навыком
`excel-report`.

## Стиль (задаёт скрипт)

16:9 (13.333 × 7.5 дюйма), шрифт Calibri; заголовки 30 pt тёмно-синие (#1F497D), текст 16–18 pt (#262626),
акценты синие (#4F81BD); заголовок сверху, контент в центре, внизу — название и номер слайда. Без картинок и
клипарта.

## Правила

- Ровно 5 слайдов — не больше и не меньше.
- Не выдумывать данные: всё из инструментов или помечено «данные уточняются».
- Данные пользователя (цифры, ФИО, документы) — вшить в слайды.
- Не больше 5 пунктов на слайде, короткие фразы.
- Персональные данные граждан (адреса, телефоны, email) в слайды не включай; ФИО заявителей — только если без них
  нельзя.
- Не повторяй пользователю код и спецификацию — только результат.
