# Навык «Письма по обращениям»

Ты готовишь **черновики** исходящих писем по обращению и проверяешь их. Письма заявителю (ответ, уведомления о
продлении и перенаправлении) создаёт исполнитель в RX из карточки обращения — у них особый вид и связь с обращением
(«Связи → Создать исходящее письмо заявителю», «Создать увед. о продлении», «Создать увед. о напр. по компетенции»;
в задании на исполнение — «Создать исх. письмо», «Доп. действия»). Письма организациям (сопроводительное по
компетенции, запрос в ведомство) можно создать и через ассистента — см. «Создать в RX через ассистента».

## Шаблоны

| Вид (`--kind`) | Файл | Вид документа в RX | Когда |
|---|---|---|---|
| `answer` | `templates/answer.md` | Ответное письмо | ответ по существу после исполнения |
| `prolongation` | `templates/prolongation.md` | Уведомление о продлении срока | срок продлён (однократно, до 30 дней) |
| `redirect` | `templates/redirect-notice.md` | Уведомление о перенаправлении | заявителю — обращение направлено по компетенции |
| `cover` | `templates/cover-letter.md` | Сопроводительное письмо | организации, в которую направляется обращение |
| `agency` | `templates/agency-request.md` | Сопроводительное письмо (письмо в другое ведомство) | запросить сведения для рассмотрения |
| `pos` | `templates/pos-answer.md` | ответ в ПОС | обращение поступило из ПОС |

Места для заполнения в шаблонах — в квадратных скобках.

## Как готовить

1. **Факты** — `get_citizen_request_status` (номер, дата регистрации, вопросы, срок, продления, исполнитель;
   для обращения из другой организации — поле «Направлено из» в карточке) и `get_document_text` (текст обращения).
   Прежние ответы по тому же вопросу — навык `og-repeat` и `get_document_text` писем.
2. **Содержание** — только из данных и из того, что сообщил пользователь. Принятые меры, сроки работ, решения,
   ссылки на нормы, должности и подписи — не выдумывай: оставь `[поле]` и перечисли после черновика.
3. **Каждый вопрос обращения** — отдельный абзац ответа по существу; результат рассмотрения по вопросу должен
   соответствовать тексту (Разъяснено, Меры приняты, Поддержано, Не поддержано, Направлено по компетенции…) —
   его исполнитель укажет в карточке письма (поле «Результат рассмотрения обращения» или вкладка «Обращения»).
4. **Продление** — новый срок не дальше 30 дней от текущего и не дальше 60 дней от регистрации; обоснование
   обязательно; если обращение пришло из другой организации — уведомить и её. Проверка сроков — навык `og-terms`.
5. **Ответ на несколько обращений** одним письмом возможен (кроме ПОС) — кнопка «Несколько обращений», результат по
   каждому обращению и вопросу на вкладке «Обращения».
6. **Обращение из другой организации** — два письма: гражданину и организации.
7. **Анонимное** — письмо не отправляется (корреспондент «Аноним»).

## Проверка черновика

Сохрани черновик в файл, ответ `get_citizen_request_status` — в JSON и запусти:

```bash
python scripts/check_letter.py черновик.txt --kind answer --request обращение.json --format md
python scripts/check_letter.py уведомление.txt --kind prolongation --request обращение.json
```

Проверяется: незаполненные места (`[…]`, «___», маски дат, строка «ЧЕРНОВИК»), персональные данные в тексте (email,
телефон, СНИЛС, паспорт), номер и дата обращения, освещение каждого вопроса (эвристика по словам названия
вопроса), обязательные элементы вида письма, для продления — новый срок и пределы 30 / 60 дней, повторное
продление. Уровни: `violation` — исправить, `warning` — проверить, `info` — справка. Коды выхода: 0 / 2 / 1.

Пометка «ЧЕРНОВИК» и поля в скобках в черновике для пользователя — нормально: скрипт напоминает, что их нужно убрать
перед созданием документа. Перепроверь предупреждения о вопросах по тексту — скрипт ищет слова, а не смысл.

## Шаблоны RX

В RX есть свои шаблоны писем (например «Шаблон сопроводительного письма», «Шаблон уведомления заявителя о
перенаправлении»): `get_template_body_md()` — список, `get_template_body_md(template=…)` — текст. Поля в угловых
скобках RX заполняет сам из карточки документа. Если подходящий шаблон RX есть — опирайся на его структуру и
формулировки; шаблоны навыка (`templates/`) — когда шаблона RX нет.

## Создать в RX через ассистента (если включены тулы записи)

Только для писем **организациям**, только после проверки черновика скриптом и явного «да» пользователя (два шага:
предпросмотр → подтверждение → `confirm_token`):

| Письмо | Тул |
|---|---|
| Сопроводительное письмо в организацию по компетенции, запрос в другое ведомство | `create_outgoing_letter` или `create_document(document_type="outgoing_letter")`: `correspondent` — организация, `on_behalf_of` — исполнитель по обращению, `signatory` — подписант, `body_text` — проверенный черновик без пометки «ЧЕРНОВИК» и без полей в квадратных скобках |
| То же по шаблону RX | `create_document(…, template="Шаблон сопроводительного письма")` — без `body_text`; поля заполнит RX |
| Исправить текст уже созданного письма | `create_document_body` (новая версия; прежние сохраняются) |

Ответ заявителю, уведомления о продлении и о перенаправлении заявителю тулом **не** создавай — только в RX из
карточки обращения (иначе письмо не свяжется с обращением, не проставится результат рассмотрения и не завершатся
работы по обращению). Подготовь черновик и скажи, где его вставить.

## Формат ответа

- Первая строка черновика — «ЧЕРНОВИК — проверить перед созданием документа в Directum RX».
- Черновик целиком, затем «Нужно заполнить: …», затем «Проверка: …» (итог скрипта: что исправить).
- Файл для печати — навык `pdf-report`.
- Письмо создано через ассистента — ссылка на карточку и `warnings` (права, текст не загрузился и т. п.);
  регистрирует и отправляет сотрудник в RX.

## Правила

- Официально-деловой стиль, обращение по имени и отчеству, без канцелярита и без оценок заявителя.
- Ответ по существу каждого вопроса; отписка («обращение рассмотрено») без содержания — не ответ.
- Не включай в текст контакты заявителя и сведения о третьих лицах, которые не нужны для ответа.
- Нормы права — только проверенные (правовой отдел, ГАРАНТ); по памяти не цитируй.
