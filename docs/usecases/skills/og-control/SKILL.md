# Навык «Контроль и отчётность»

Ты готовишь для руководителя и сотрудников отдела сводки контроля сроков и статистику по обращениям. Сводку считает
скрипт по данным mcpOGV; статистику по ТОТК — инструмент `get_citizen_requests_analytics`.

## Что есть в Directum RX и чем это заменяет ассистент

| В RX (обложка модуля, вкладка «Обращения граждан») | Ассистент |
|---|---|
| Список «Обращения с истекающим сроком» (истёк или истекает через 7 дней) | `list_citizen_requests_due(within_days=7)` + скрипт `due_digest.py` |
| «Поручения по обращениям», отчёт «Контроль исполнения поручений по обращениям» | `list_employee_action_items`, `get_department_discipline` |
| «Статистика по обращениям граждан» (для вышестоящих органов) | `get_citizen_requests_analytics` по уровням ТОТК |
| «Статистика по вопросам в разрезе муниципальных районов» | в mcpOGV нет разреза по районам — сформируй отчёт в RX |
| Реестр обращений, журнал регистрации, «Контроль обработки входящих документов» | `find_documents(kind="citizen_request")` — поиск; журналы и официальные отчёты — в RX |
| Статус в ПОС, реестры обмена и обратной связи ПОС | в mcpOGV нет — смотреть в RX (модуль «Интеграция с ПОС») |

Официальные отчёты в вышестоящие органы формируются в RX; ассистент готовит оперативные справки и черновики.

## Сводка сроков — скрипт

1. `list_citizen_requests_due(within_days=7, include_overdue=true, limit=50)` (по исполнителю — `assignee=…`).
2. Ответ сохрани в файл как есть и запусти:

```bash
python scripts/due_digest.py горящие.json --today 2026-09-29 --format md        # сводка по-русски
python scripts/due_digest.py горящие.json --format json                         # данные
python scripts/due_digest.py горящие.json --format xlsx-spec > spec.json        # спецификация для excel-report
```

Скрипт берёт только обращения в работе, пересчитывает дни до срока, делит на группы (просрочено больше 10 дней,
1–10, сегодня, 1–3, 4–7, позже, без срока), считает по исполнителям (в работе, просрочено, макс. просрочка, срок в
7 дней) и список самых просроченных (`--top`). Если инструмент вернул не всё (`total` больше, чем в `items`) —
в `notes` предупреждение: скажи пользователю, что сводка неполная, и сузь запрос по исполнителям.
Коды выхода: 0 / 2 (плохой вход) / 1.

Excel: `python ../excel-report/scripts/build_xlsx.py spec.json сроки.xlsx` — два листа, просроченные выделены.

## Статистика по ТОТК

`get_citizen_requests_analytics(level=…, date_from, date_to, classifier_code, top)`:
- уровни: `section` — раздел, `topic` — тематика, `theme` — тема, `question` — вопрос (в RX поле Topic — тематика,
  Theme — тема; пользователю называй уровни по ТОТК);
- `requests` — обращений, `questions` — вопросов: не путай, в одном обращении несколько вопросов;
- `requests_unclassified` — без классификации: всегда упоминай, это влияет на полноту;
- `review_results` — итоги рассмотрения по вопросам.

Тема словами — сначала `search_citizen_request_classifier`, затем аналитика с `classifier_code`. Период не назван —
спроси; если торопятся — текущий месяц, и скажи об этом.

## Справка руководителю

Коротко, с цифрами и ссылками:
1. Итог: в работе N, просрочено X, истекает в 7 дней Y (из `due_digest.py`).
2. Самые просроченные — до 10, со ссылками и исполнителями.
3. Исполнители с просрочкой — таблица по убыванию.
4. Тематика за период — топ-5 тематик (обращений и вопросов), без классификации — сколько.
5. Что предлагается: продления (навык `og-terms`), перераспределение, напоминания исполнителям.

Файл — `pdf-report` (справка) или `excel-report` (таблицы для фильтрации).

## Правила

- Цифры — только из инструментов и скрипта; ФИО заявителей в сводках и статистике не выводи.
- Всегда называй, что считаешь: «обращений», «вопросов», «дней просрочки».
- Сводка по исполнителям подчинённых доступна руководителю, по всем — администратору («Нет доступа» — объясни это).
