# Навык «PDF-отчёт»

Скрипт `scripts/build_pdf.py` собирает аккуратный PDF (A4, книжная или альбомная ориентация) из JSON-спецификации.
Ты не пишешь код вёрстки — ты готовишь спецификацию из реальных данных тулов и вызываешь скрипт.

## Когда использовать

- «Сделай отчёт в PDF», «подготовь справку для руководителя», «нужен документ на печать».
- Нужен читаемый документ с выводами, пояснениями и таблицами до нескольких тысяч строк.
- Если пользователь хочет **фильтровать/сортировать/считать** данные или строк больше 5000 — используй навык `excel-report`.

## Как вызвать

```bash
python scripts/build_pdf.py spec.json /путь/к/отчёт.pdf
# или спецификация через stdin:
cat spec.json | python scripts/build_pdf.py - /путь/к/отчёт.pdf
```

Из Python: `from build_pdf import build; path = build(spec_dict, "отчёт.pdf")` (при ошибке — `SpecError`).

Зависимость: `pip install -r requirements.txt` (reportlab). Сеть не нужна.

| Код выхода | Значение | Что делать |
|---|---|---|
| 0 | Успех, в stdout — абсолютный путь к PDF | Отдай файл пользователю |
| 2 | Ошибка спецификации (или пути вывода), в stderr — список «поле: что не так» | **Исправь спецификацию по сообщению и вызови ещё раз.** Не меняй данные «на глаз» |
| 1 | Непредвиденная ошибка (нет шрифта, нет прав на запись и т. п.) | Сообщи пользователю текст ошибки |

Пример сообщения при коде 2:
```
Ошибка спецификации:
- blocks[3].rows[2]: ожидалось 5 значений, получено 4
- blocks[3].rows[7][4].url: допустимы только ссылки http:// или https://, получено «javascript:alert(1)»
```

Файл пишется атомарно: сначала во временный файл в той же папке, затем переименовывается. Недописанный PDF
не остаётся. Папки создаются автоматически. Путь вывода обязан оканчиваться на `.pdf`.

## Формат спецификации

Схема (комментарии `//` здесь только для пояснения — в настоящем JSON их быть не должно). Полный рабочий пример —
`examples/example_spec.json`.

```jsonc
{
  "title": "Заголовок отчёта",               // обязательно
  "subtitle": "Подзаголовок",                // необязательно
  "author": "Кто подготовил",                // необязательно, идёт в метаданные PDF
  "date": "2026-09-28",                      // необязательно, выводится как 28.09.2026
  "orientation": "portrait",                 // "portrait" (по умолчанию) или "landscape" — для широких таблиц
  "blocks": [ ... ]                          // обязательно, блоки по порядку
}
```

Неизвестные поля — ошибка (так ловятся опечатки вроде `colums`).

### Блоки

| type | Поля | Описание |
|---|---|---|
| `heading` | `text`, `level` (1–3, по умолчанию 1) | Заголовок раздела |
| `paragraph` | `text` | Абзац. Поддерживает `**жирный**`, `[текст](https://…)` и переводы строк `\n` |
| `bullets` | `items` (список), `title`? | Маркированный список; пункт — строка или ссылка `{"text","url"}` |
| `key_value` | `pairs`, `title`? | Пары «подпись — значение»: `[["Сотрудник","Иванов"], …]`, или `[{"label":…,"value":…}]`, или объект `{"Сотрудник":"Иванов"}` |
| `table` | `columns`, `rows`, `caption`?, `totals`?, `font_size`? | Таблица (см. ниже) |
| `note` / `warning` | `text`, `title`? | Выделенная плашка: синяя «Примечание» / красная «Внимание» |
| `page_break` | — | Разрыв страницы |

### Таблица

```json
{
  "type": "table",
  "caption": "Таблица 1. Просроченные поручения",
  "columns": [
    {"title": "Тема", "width": 4},
    {"title": "Срок", "width": 1.3, "align": "center"},
    {"title": "Дней просрочки", "align": "right"},
    "Кто выдал"
  ],
  "rows": [
    ["Подготовить справку", "2026-09-28T00:00:00+04:00", 12, "Петров П. П."]
  ],
  "totals": ["Итого: 1", null, 12, null]
}
```

- `columns[i]`: объект `{"title", "width"?, "align"?}` или просто строка-заголовок.
  `width` — **относительный вес** (по умолчанию 1): ширины пропорционально делят ширину страницы.
  `align` — `left` (по умолчанию), `center`, `right`.
- `rows` — список строк, каждая строка — список ровно из стольких значений, сколько колонок.
- `totals` — необязательная итоговая строка (тот же формат, что строка), выводится жирной внизу. Итоги считай сам
  **из тех же данных**, что в таблице.
- `font_size` — 5–14; по умолчанию 9 (≤6 колонок), 8 (≤10), 7 (больше).
- Пустая таблица (`"rows": []`) выводится со строкой «Нет данных».
- Шапка повторяется на каждой странице, текст в ячейках переносится, очень длинная ячейка переносится на следующую страницу.

### Значения (ячейки, пункты списков, значения key_value)

| Значение | Вывод |
|---|---|
| `null` | пустая ячейка |
| строка | как есть; `**жирный**` и `[текст](https://…)` работают |
| `"2026-09-28"` | 28.09.2026 |
| `"2026-09-28T00:00:00+04:00"` | 28.09.2026 (полночь — только дата) |
| `"2026-09-28T14:05:00+04:00"` | 28.09.2026 14:05 (время как в строке, без пересчёта пояса) |
| число `1234567` / `12.5` | `1 234 567` / `12,5` (до 2 знаков после запятой) |
| `true` / `false` | Да / Нет |
| `{"text": "Открыть", "url": "https://…"}` | кликабельная ссылка |

Разрешены только ссылки `http://` и `https://`. `javascript:`, `file:`, `data:` и т. п. — ошибка (код 2).

### Полный пример

```json
{
  "title": "Просроченные поручения сотрудника",
  "subtitle": "Иванов Иван Иванович — входящие поручения в работе",
  "author": "Аналитический отдел",
  "date": "2026-09-28",

  "blocks": [
    {"type": "heading", "level": 1, "text": "Сводка"},
    {"type": "key_value", "pairs": [["Сотрудник", "Иванов Иван Иванович"], ["Всего просрочено", 2]]},
    {"type": "paragraph", "text": "Срок исполнения поручений **истёк**. Карточки — в [Directum RX](https://rx.example.gov.ru/DirectumRX)."},
    {"type": "warning", "text": "Одно поручение просрочено более чем на 30 дней."},
    {"type": "table",
     "caption": "Таблица 1. Просроченные поручения",
     "columns": [
       {"title": "Тема", "width": 4},
       {"title": "Срок", "width": 1.3, "align": "center"},

     ],
```

## Как превратить результаты mcpOGV в спецификацию

### Просроченные поручения сотрудника (`admin_list_employee_action_items`)

Вызов: `admin_list_employee_action_items(employee="Иванов", direction="incoming", only_overdue=true, limit=50)`.
Ответ: `{"items": [{"id", "subject", "deadline", "days_overdue", "author", "performer", "url", ...}], "total", "returned", "truncated", "employee": {...}}`.

Каждый элемент `items` → строка таблицы:

```json
{
  "type": "table",
  "caption": "Просроченные поручения: Иванов И. И.",
  "columns": [
    {"title": "Тема", "width": 4},
    {"title": "Срок", "width": 1.3, "align": "center"},
    {"title": "Дней просрочки", "width": 1.2, "align": "right"},
    {"title": "Кто выдал", "width": 2},
    {"title": "Ссылка", "width": 1.2}
  ],
  "rows": [
    ["<item.subject>", "<item.deadline как есть>", "<item.days_overdue>", "<item.author>", {"text": "Открыть", "url": "<item.url>"}]
  ]
}
```

- `deadline` передавай как пришёл (ISO) — скрипт сам выведет ДД.ММ.ГГГГ.
- Для исходящих (`direction="outgoing"`) колонку «Кто выдал» замени на «Исполнитель» (`item.performer`).
- Если `url` пуст — ставь `null`, а не выдуманную ссылку.
- Если `truncated: true` — добавь блок `note`: «Показано N из total. Полный список — в Excel-выгрузке» и при
  необходимости запроси больше записей.

### Обращения граждан по тематикам (`get_citizen_requests_analytics`)

Ответ: `{"level_label", "date_from", "date_to", "requests_total", "requests_unclassified", "groups": [{"code", "name", "requests", "questions"}], "groups_total", "review_results": [{"label", "count"}]}`.

- Блок `key_value`: «Период» (`date_from`–`date_to`), «Всего обращений» (`requests_total`), «Без классификации» (`requests_unclassified`).
- Таблица по `groups`: колонки «Код», «Тематика» (`level_label` с заглавной), «Обращений» (`requests`), «Вопросов» (`questions`).
  Не путай обращения и вопросы: в одном обращении бывает несколько вопросов.
- Таблица по `review_results`: «Итог рассмотрения», «Количество».
- Если `groups_total` > числа строк — добавь `note`: «Показаны первые N из groups_total тематик».

## Правила

1. **Никогда не выдумывай данные.** Все цифры, темы, ФИО, даты и ссылки — только из ответов тулов. Нет данных —
   пустая таблица («Нет данных») или `null` в ячейке, а не догадка.
2. **Сохраняй ссылки** на карточки RX (`url`) — в виде `{"text": "Открыть", "url": …}`.
3. Даты — в ISO из тула или ДД.ММ.ГГГГ; скрипт сам приводит ISO к ДД.ММ.ГГГГ.
4. **Персональные данные граждан** (ФИО заявителя, адрес, телефон, e-mail, текст обращения) в отчёт не включай,
   если пользователь явно не попросил и это не нужно для задачи. Для аналитики достаточно тематик и чисел.
5. Итоги, доли и средние считай только из данных, попавших в отчёт, и подписывай, что именно посчитано.
6. Широкие таблицы (5+ колонок) — `"orientation": "landscape"`.
7. После успешного вызова отдай пользователю путь к файлу и кратко перескажи содержание (что вошло, сколько строк).

## Лимиты

| Что | Максимум |
|---|---|
| Блоков в отчёте | 500 |
| Строк в одной таблице | 5 000 (≈15 с сборки; больше — используй Excel) |
| Ячеек во всех таблицах | 60 000 |
| Колонок в таблице | 30 |
| Пунктов в списке / пар в key_value | 2 000 / 500 |
| Символов в ячейке | 20 000 |
| Символов в абзаце | 100 000 |
| Символов в заголовке/подписи | 500 |
| Длина ссылки | 2 000 |
| Размер файла спецификации | 30 МБ |

## Шрифты

Кириллица требует TTF-шрифт. Порядок поиска:
1. Переменные окружения `PDF_FONT_REGULAR` и `PDF_FONT_BOLD` (пути к .ttf);
2. `fonts/DejaVuSans.ttf` и `fonts/DejaVuSans-Bold.ttf` в папке навыка (входят в поставку, лицензия — `fonts/LICENSE-DejaVu.txt`);
3. системные DejaVu/Liberation (Linux), Arial (Windows/macOS).

Если шрифт не найден — код 1 с понятным сообщением.

В колонтитуле каждой страницы: «Сформировано: ДД.ММ.ГГГГ ЧЧ:ММ» (время сборки) и «стр. N из M».
