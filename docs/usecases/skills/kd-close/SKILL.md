# Навык «Снятие с контроля»

Ты проверяешь, можно ли снять поручение с контроля, вместо ручной проверки «все ли поручения выполнены».
Снимает контролёр в RX: принимает работы в задании на приёмку («Примите работы») или завершает контроль штатно —
ассистент этого не делает.

## Данные

- Досье: `get_control_dossier(action_item_id)` → сохрани JSON как есть.
- Кандидаты на снятие: `list_controlled_action_items(state="on_acceptance", supervisor=ФИО контролёра)` — исполнено и ждёт
  вашей приёмки.

## Скрипт

```bash
python scripts/close_readiness.py досье.json --format md
python scripts/close_readiness.py досье.json            # JSON
```

Проверяет:
- **блокеры**: не завершены поручения дерева (кроме корневого, если оно уже на приёмке); не рассмотрен запрос на
  продление;
- **предупреждения**: завершено без отчёта; есть прекращённые поручения; последняя приёмка — «на доработку»;
  срок нарушен;
- **факты**: ждёт приёмки или принято (кем и когда), исполнено в срок или с нарушением на N дней, сколько раз
  переносился срок и на сколько, число отчётов и документов.

Результат: `ready`, `blockers`, `warnings`, `facts`, `draft_reason` (только если готово). Коды выхода: 0 / 2 / 1.
Названия документов в причину не попадают: в них бывают ФИО заявителей.

## Как излагать

1. «Готово к снятию» или «Не готово: N причин».
2. Блокеры — списком, с номерами поручений и исполнителями; что сделать с каждым.
3. Предупреждения — что проверить перед снятием (например, открыть отчёт через `get_document_text`).
4. Черновик причины снятия — дословно из `draft_reason`, контролёр правит и вставляет в RX.
5. Если исполнено с нарушением срока — прямо скажи, это должно быть отражено.

Для списка кандидатов: прогони скрипт по досье каждого (до 10–15) и дай таблицу «Поручение — готово — что мешает».

## Правила

- Не утверждай, что работа выполнена по существу, только потому, что задания закрыты: при сомнении прочитай
  отчёт и результат.
- Решение принимает контролёр; ты показываешь основания.
