# Навык «Мониторинг контроля»

Ты делаешь для контролёра ежедневную сводку по поручениям на контроле. Контрольных карт в системе нет: объект
контроля — само поручение с признаком «На контроле» и контролёром. Цель сводки — показать, **кому звонить первым и
почему**, а не пересказать реестр по датам.

## Данные

1. Реестр: `list_controlled_action_items` — по умолчанию `state="in_work"`, `limit=100`. Периметр контролёра —
   `supervisor="me"`; по исполнителю, автору, соисполнителю — соответствующие параметры; окно срока — `due`
   (`today`, `tomorrow`, `next_3_days`, `this_week`, `next_week`, `this_month`).
2. Досье (точнее прогноз): `get_control_dossier(id)` для поручений со сроком в ближайшие 7 дней и для уже
   «подозрительных» — не больше 10–15 за раз. Без досье скрипт считает только по срокам и скажет об этом.
3. Ответы тулов сохрани в файлы как есть: реестр — одним JSON, досье — списком JSON.

## Скрипт

```bash
python scripts/risk_score.py реестр.json --dossiers досье.json --today 2026-09-29 --format md
python scripts/risk_score.py реестр.json --today 2026-09-29            # JSON
```

Балл складывается из признаков, у каждого — причина в `reasons`:

| Признак | Баллы |
|---|---|
| Срок сегодня или завтра | 2 |
| До срока 2–3 дня | 1 |
| Прошло 80 % срока и больше | 1 |
| У исполнителя 5+ поручений на контроле со сроком в 7 дней | 1 |
| Срок переносился: один раз / два и больше (из досье) | 1 / 2 |
| Не рассмотрен запрос на продление (из досье) | 1 |
| Просрочены подпоручения (из досье) | 2 |
| Нет движения 14+ дней: отчётов, подпоручений, переписки (из досье) | 1 |

Группы: 3 балла и больше — «сорвётся», 1–2 — «под угрозой», 0 — «в норме». Отдельно, до баллов: «просрочено»
(срок прошёл), «ждёт приёмки» (исполнено, решение за контролёром), «без срока». `bottlenecks` — исполнители
с просрочкой или «сорвётся». `notes` — если реестр или досье неполные. Коды выхода: 0 / 2 / 1.

## Как излагать сводку

1. Итог одной строкой: «На контроле N: просрочено X, ждёт вашей приёмки Y, сорвётся Z, под угрозой W».
2. **Ждёт приёмки** — первым: это работа самого контролёра (принять или вернуть на доработку в задании RX).
3. Просрочено и «сорвётся» — таблица «Поручение (ссылка) — исполнитель — срок — почему», причины — из `reasons`.
4. Узкие места — кто держит больше всего риска.
5. Что предлагается: позвонить исполнителю, запросить промежуточный отчёт, проверить запрос на продление
   (навык `kd-dossier` — подробности по поручению), снять исполненное (навык `kd-close`).
6. Выгрузка — `excel-report`, справка — `pdf-report`.

## Правила

- Прогноз — подсказка, а не оценка людей; не пиши «исполнитель плохо работает».
- Не выдумывай причин, которых нет в `reasons`.
- Если реестр обрезан (`truncated`, `notes`) — скажи, что сводка неполная, и сузь периметр.
