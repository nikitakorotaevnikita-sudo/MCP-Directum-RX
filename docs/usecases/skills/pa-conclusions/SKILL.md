# Навык «Заключения и документы этапов»

По описанию решения Directum RX «Правовые акты органов власти» на этапах согласования создаются документы:
- **Заключение** (простой документ вида «Заключение») — при результате «Отказ с заключением» у внешнего ведомства;
  без него RX не даст выполнить задание;
- **Заключение ГПУ** — при отказе в согласовании со стороны государственно-правового управления;
- **Заключение ОРВ** — ответственный за ОРВ после положительных результатов публичных процедур;
- текст задания с замечаниями — при «Согласовать с замечаниями» или «На доработку»;
- **сопроводительное письмо** — для неавтоматизированных ведомств и для рассылки подписанного ПА.

Ты готовишь **черновики** по шаблонам из папки `templates/`. Заключение, которое нужно приложить к заданию
согласования («Отказ с заключением»), сотрудник создаёт в RX кнопкой «Создать заключение» в самом задании — так оно
попадает во вложения задания. Сопроводительное письмо, служебную записку с замечаниями и новую редакцию текста
проекта можно создать и через ассистента — см. «Создать в RX через ассистента».

## Шаблоны

| Файл | Когда |
|---|---|
| `templates/gpu-refusal.md` | Заключение ГПУ об отказе в согласовании проекта |
| `templates/agency-refusal.md` | Заключение внешнего ведомства об отказе (результат «Отказ с заключением») |
| `templates/normcontrol-remarks.md` | Замечания по результатам нормоконтроля и лингвистической экспертизы |
| `templates/orv-conclusion.md` | Заключение об оценке регулирующего воздействия |
| `templates/task-remarks.md` | Текст задания при «Согласовать с замечаниями» / «На доработку» |
| `templates/cover-letter.md` | Сопроводительное письмо ведомству (согласование на бумаге или рассылка ПА) |

Места для заполнения в шаблонах отмечены квадратными скобками: `[реквизиты проекта]`.

## Как заполнять

1. **Реквизиты** — из mcpOGV: `get_legal_act(act_id)` — вид, номер, дата, наименование, разработчик
   (`prepared_by`), подразделение, подписант, этап; ссылка на карточку.
2. **Содержание замечаний и оснований** — из результатов других навыков, а не придуманное:
   - нормоконтроль — `pa-normcontrol`;
   - правовые основания и ссылки на нормы — `pa-legal-basis` (реквизиты актов и редакции — по ГАРАНТу);
   - коррупциогенные факторы — `pa-anticorruption`;
   - ОРВ — `pa-orv`;
   - что изменилось между версиями — `pa-compare`.
3. **Нормы права в заключении** — только с реквизитами и редакцией из ГАРАНТа (`garant_document_info`,
   `garant_snippets`). Нет подтверждения в ГАРАНТе — не ссылайся.
4. **Незаполненные места.** Если данных для поля нет (исходящий номер письма, ФИО подписанта ведомства, срок
   обсуждений) — оставь пометку в квадратных скобках и **перечисли их после черновика**: «Нужно заполнить: …».
   Не подставляй правдоподобные значения.
5. Удали из шаблона разделы, которые не применимы (например, раздел о коррупциогенных факторах, если они не
   выявлены — тогда напиши «не выявлены»).

## Шаблоны RX

В RX есть шаблоны документов, например «Шаблон нормативного правового акта», «Шаблон сопроводительного письма»:
`get_template_body_md()` — список, `get_template_body_md(template=…)` — текст. Если подходящий шаблон RX есть —
бери его структуру; поля в угловых скобках RX заполнит сам при создании документа по шаблону.

## Создать в RX через ассистента (если включены тулы записи)

Только когда в черновике не осталось полей в квадратных скобках, и только после явного «да» пользователя (два шага:
предпросмотр → подтверждение → `confirm_token`). `on_behalf_of` — юрист, от чьего имени документ.

| Документ | Тул |
|---|---|
| Сопроводительное письмо ведомству | `create_document(document_type="outgoing_letter", correspondent=…, signatory=…, body_text=…)` или по шаблону RX (`template=…`, без `body_text`) |
| Замечания по нормоконтролю, заключение ОРВ, иное внутреннее заключение | `create_document(document_type="memo" или "simple_document", document_kind=…, body_text=…, body_markdown=true)` — вид документа как в RX; связь с проектом — `leading_document_id` только для `addendum` |
| Новая редакция текста проекта после доработки | `create_document_body(document_id=проект, text=…, markdown=true)` — новая версия, прежние сохраняются |
| Отправить проект на согласование | `send_document_for_approval` |

Не создавай тулом заключение для «Отказа с заключением» внешнего ведомства или ГПУ — его нужно создать в задании
согласования в RX, иначе RX не даст выполнить задание. Подготовь текст и скажи, куда его вставить.

## Формат ответа

- Черновик документа целиком (markdown), затем список «Нужно заполнить» и «На что опирается» (какие проверки и
  документы ГАРАНТа использованы).
- Документ создан через ассистента — ссылка на карточку и `warnings`; регистрацию, подписание и отправку делает
  сотрудник в RX.
- Если нужен файл для печати или вложения — навык `pdf-report` (или по просьбе — `excel-report` для таблицы
  замечаний).
- Первая строка черновика — «ЧЕРНОВИК — проверить перед созданием документа в Directum RX».

## Правила

- Официально-деловой стиль, без эмоциональных оценок. Каждое замечание — со ссылкой на пункт проекта и основание.
- Отказ в согласовании должен быть мотивирован: какая норма нарушена или какое положение неприемлемо и почему.
- Не пиши от имени конкретного должностного лица то, чего оно не утверждало: подпись и должность — поля для
  заполнения, а не догадка.
