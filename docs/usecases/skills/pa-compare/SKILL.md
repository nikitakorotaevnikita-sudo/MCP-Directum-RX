# Навык «Сравнение редакций»

Ты показываешь отличия между двумя текстами правового акта по существу: какие пункты добавлены, исключены,
изменены и перенумерованы. Сравнение делает скрипт — он не пропускает мелкие правки и не «додумывает» изменения;
ты объясняешь результат.

## Откуда брать тексты

| Сравнение | Как получить тексты |
|---|---|
| Проект ↔ принятый акт | `get_legal_act(id проекта)` → `adopted_act.id`; `get_document_text` обоих |
| Две версии проекта (до и после доработки) | `get_document_text` берёт последнюю версию; предыдущую версию пользователь может выгрузить из RX и передать файлом |
| Акт ↔ федеральная или региональная норма | текст нормы из ГАРАНТа: `garant_export_html` / `garant_export_block_html`, нужная редакция — `garant_document_redactions` |
| Два файла пользователя | тексты из файлов |

Если один из текстов недоступен (`message` про скан, нет файла, `truncated: true`) — скажи об этом и не сравнивай
по памяти. Для обрезанного текста запроси больший `max_chars`.

## Скрипт

```bash
python scripts/compare_texts.py старая.txt новая.txt                 # JSON
python scripts/compare_texts.py старая.txt новая.txt --format md     # отчёт по-русски
python scripts/compare_texts.py старая.txt новая.txt --context 12    # больше слов контекста вокруг правок
```

Скрипт делит тексты на единицы: преамбула, пункты по нумерации («1.», «1.1.», «2)», «а)»), приложения; сопоставляет
по номерам; пункты, которые только перенумерованы (текст совпадает на 90 % и больше), отдаёт отдельно; различия
только в пробелах, типе кавычек и тире не считает изменениями. Результат JSON: `summary`, `added`, `removed`,
`changed` (`before`, `after`, `similarity`, пословный `diff`), `renumbered`. Код 2 — один из файлов пустой
или не найден.

Если в текстах нет нумерации, скрипт сравнивает абзацы — предупреди пользователя, что сопоставление менее точное.

## Как излагать результат

1. Итог первой строкой: «Добавлено N, исключено M, изменено K пунктов, перенумеровано L».
2. **Существенные изменения** — сначала: новые обязанности, сроки, субъекты, суммы, основания, исключения; изменение
   смысла (например, «обязан» → «вправе» — это важно для антикоррупционной экспертизы, отметь).
3. Таблица изменённых пунктов:

| Пункт | Было | Стало | Суть изменения |
|---|---|---|---|

   «Было» и «Стало» — дословно из `before`/`after` (можно сократить неизменную часть многоточием); «Суть» — одна
   фраза твоими словами.
4. Добавленные и исключённые пункты — списком с текстом.
5. Перенумерация — одной строкой («пункты 4–7 стали 5–8»), без подробностей.
6. Чисто редакционные правки (запятые, порядок слов без изменения смысла) — сгруппируй в одну строку, не расписывай.

Для оформления — навык `pdf-report` (таблица «Было / Стало») или `excel-report`, если изменений много.

## Правила

- Не утверждай об изменениях, которых нет в результате скрипта; не пропускай изменения из результата.
- Смысловую оценку («расширены полномочия», «сужены права») давай осторожно и только по тексту.
- Если сравниваешь с актом из ГАРАНТа — укажи редакцию и дату, на которую взят текст.
