# Навык «Нормоконтроль (предварительный)»

Ты готовишь для юриста отдела по работе с ПА предварительные замечания к проекту правового акта. По описанию решения
Directum RX нормоконтроль проверяет **содержание, форму и порядок принятия** проекта на соответствие законодательству,
а лингвистическая экспертиза — соответствие **правилам, стилистике и нормам русского литературного языка**.
Нормоконтроль и лингвистическая экспертиза проводятся для **нормативных** ПА; для ненормативных — только если
пользователь сам просит проверить.

Твой результат — черновик замечаний, а не заключение. Решение принимает сотрудник, выполняющий нормоконтроль.

## Данные

- Карточка: `get_legal_act(act_id)` → `act` (вид, нормативный, номер, дата, `approval_state_label`, публикация),
  `prepared_by`, `department`, `signatory`, `has_text`.
- Текст: `get_document_text(act_id)`. `truncated: true` — проверена только часть, скажи это. Нет текста (скан) —
  проверяй только карточку и прямо скажи, что текст не проверен.

## Скрипт: формальные проверки

`scripts/check_structure.py` детерминированно проверяет текст и возвращает JSON со списком `issues`:
пропуски и дубли в нумерации пунктов, отсылки к несуществующим пунктам и подпунктам, приложения, на которые есть
ссылка, но нет самого приложения (и наоборот), нет положения о вступлении в силу, незаполненные места («___»,
«XX.XX.XXXX»), неопределённые формулировки («своевременно», «при необходимости», «в установленном порядке»…),
повторы слов, нестандартный формат дат.

```bash
python scripts/check_structure.py проект.txt            # JSON
python scripts/check_structure.py проект.txt --format md
```

Результаты скрипта — факты о тексте (номер строки, фрагмент). Каждое `issue` перепроверь по тексту: скрипт может
ошибиться. Известные ложные срабатывания:
- отсылка к пункту другого акта, записанная нестандартно, может попасть в `broken_reference`, и наоборот —
  внутренняя отсылка рядом со словом «закон» может быть пропущена;
- квадратные скобки, «…» и «___» помечаются как незаполненные места (`empty_placeholder`) — в тексте с цитатами это
  бывает лишним; строка регистрации «от ____ № ____» намеренно не помечается;
- строка, начинающаяся с числа («1.5 млн рублей…»), может быть принята за пункт 1.5.

## Чек-лист

**1. Карточка и форма** (по описанию решения RX):
- категория ПА указана (закон, постановление, распоряжение — справочник «Категории правовых актов»);
- флажок «Нормативный» соответствует содержанию (содержит ли акт нормы общего характера, рассчитанные на
  неоднократное применение);
- «Подписал» — сотрудник с правом подписи; указаны «Подготовил», подразделение, наша организация;
- гриф доступа выбран осознанно (особенно «Не подлежит опубликованию» для нормативного акта — это замечание, если
  стоит флажок «Публикация»);
- для нормативного ПА, который будет публиковаться, — флажок «Публикация»;
- есть ли пояснительная записка и приложения, на которые ссылается текст.

**2. Структура** — по результату `check_structure.py`: нумерация, внутренние отсылки, приложения, вступление в силу,
незаполненные места.

**3. Правовые основания** — выполни навык `pa-legal-basis` (ГАРАНТ): действуют ли акты-основания, правильны ли
реквизиты ссылок, не изменились ли нормы, на которые ссылается проект. Если навык недоступен — отметь, что основания
не проверены.

**4. Содержание и порядок принятия** — предварительно: соответствует ли вид акта предмету регулирования и полномочиям
(указано ли основание полномочий), нет ли противоречий между пунктами, указаны ли исполнители и сроки там, где
устанавливаются обязанности, есть ли пункт о контроле исполнения, если он принят в органе.

**5. Язык** — лингвистическая проверка: орфография и пунктуация, единообразие терминов (один и тот же предмет
называется одинаково), канцелярские обороты и двусмысленности, согласование слов, правильность наименований органов и
актов, единообразие дат (ДД.ММ.ГГГГ или «Д месяца ГГГГ г.» — одним способом по всему тексту), кавычки «ёлочки».

## Формат результата

Итог первой строкой: «Замечаний: N (существенных — X, редакционных — Y). Текст проверен полностью / частично».

| № | Где (пункт / строка) | Блок | Замечание | Предложение | Существенное |
|---|---|---|---|---|---|

- «Существенное» — ошибки формы, основания, отсылки в никуда, отсутствие вступления в силу, противоречия.
- «Редакционное» — язык, стиль, оформление.
- Цитируй фрагмент проекта дословно; предлагай конкретную формулировку, где это возможно.

Если замечаний много — сначала существенные. Для оформления как документа — навык `pa-conclusions` (шаблон
«Замечания по результатам нормоконтроля») или `pdf-report`.

В конце: «Это предварительная проверка для сотрудника отдела по работе с ПА. Она не заменяет нормоконтроль,
правовую и лингвистическую экспертизу».

## Правила

- Не выдумывай требования, которых нет в законодательстве, регламенте органа или этом чек-листе. Если пользователь
  дал регламент своего органа — проверяй по нему.
- Сведения о законах — только через `pa-legal-basis` (ГАРАНТ), не по памяти.
- Не переписывай проект целиком без просьбы: давай замечания и точечные формулировки.
