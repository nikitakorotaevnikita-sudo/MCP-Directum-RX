# Навык «Сроки по 59-ФЗ»

Ты проверяешь сроки обращений: не нарушены ли они и что можно сделать. Расчёт делает скрипт — детерминированно и
одинаково каждый раз; ты объясняешь результат и предлагаешь действия.

## Нормы (общие положения — сверяйся с регламентом органа)

| Что | Срок | Основание | В Directum RX |
|---|---|---|---|
| Регистрация письменного обращения | 3 дня с поступления | ч. 2 ст. 8 59-ФЗ | по умолчанию 3 рабочих дня (настраивается) |
| Направление по компетенции | 7 дней с регистрации, с уведомлением заявителя | ч. 3 ст. 8 | «Направление по компетенции» при рассмотрении |
| Рассмотрение | 30 дней с регистрации | ч. 1 ст. 12 | «Срок исполнения» по умолчанию 30 дней, выходной — перенос на последний рабочий день |
| Продление | однократно, не более чем на 30 дней, с уведомлением заявителя | ч. 2 ст. 12 | «Уведомление о продлении срока» или запрос продления поручения; общий срок — не более 60 дней |
| Отметки органа | Оперативно — до 10 дней, Срочно — до 3 дней | регламент | отметки в карточке |

Сроки 59-ФЗ — **календарные** дни. Срок каждого обращения уже рассчитан в RX (`deadline`, `initial_deadline`) —
опирайся на него. `add_working_days` — только для внутренних сроков в рабочих днях.

## Данные

- Одно или несколько обращений: `get_citizen_request_status` (номер, id или ФИО, до 20).
- Все горящие: `list_citizen_requests_due(within_days=…, limit=50)`.

Ответ инструмента сохрани в файл как есть (JSON) и передай скрипту.

## Скрипт

```bash
python scripts/check_terms.py ответ.json --today 2026-09-29             # JSON
python scripts/check_terms.py ответ.json --today 2026-09-29 --format md # таблица по-русски
python scripts/check_terms.py ответ.json --soon-days 10                 # окно «истекает» (по умолчанию 7)
```

Принимает ответ `get_citizen_request_status` / `list_citizen_requests_due`, список обращений или одно обращение.
Коды выхода: 0 — успех, 2 — плохой вход (сообщение в stderr — исправь и повтори), 1 — непредвиденная ошибка.

Коды замечаний (`issues[].code`), уровень `violation` — нарушение, `warning` — внимание, `info` — справка:

| Код | Что значит |
|---|---|
| `not_registered` | не зарегистрировано и прошло больше 3 рабочих дней с поступления |
| `registration_late` / `registration_late_calendar` | зарегистрировано позже 3 рабочих / 3 календарных дней |
| `initial_deadline_over_30` | исходный срок больше 30 дней с регистрации |
| `multiple_prolongations`, `prolongation_over_30`, `total_over_60` | нарушены пределы продления |
| `prolongation_not_recorded`, `prolongation_without_reason` | срок увеличен без записи о продлении или без причины |
| `answered_late` | ответ позже срока (по дате ответа или регистрации письма) |
| `overdue`, `due_today`, `due_soon` | в работе: срок нарушен, сегодня, в окне |
| `no_deadline` | в работе без срока |
| `review_result_missing` | рассмотрено, но у вопроса нет результата рассмотрения |
| `question_not_classified` | вопрос без кода ТОТК |
| `prolongation_possible` | подсказка: продление ещё возможно |

`metrics` — дни регистрации (календарные и рабочие), срок рассмотрения, общий срок, дни продления, дней до срока
и просрочки. Рабочие дни скрипт считает без праздников — при сомнении пересчитай с `add_working_days`.

## Как излагать результат

1. Итог первой строкой: «Проверено N обращений: нарушений у X, внимание — Y, просрочено Z».
2. Нарушения — таблицей «Обращение (ссылка) — срок — что нарушено — что сделать».
3. Что сделать:
   - истекает и ответ не готов — продление: руководитель (автор резолюции) одобряет запрос исполнителя, заявителю
     направляется уведомление о продлении (навык `og-letters`, вид `prolongation`); продлить можно до истечения
     срока, один раз;
   - уже продлено — продлевать нельзя, только ускорить ответ;
   - просрочено — сообщить руководителю, ускорить ответ, при необходимости — объяснение исполнителя;
   - нет результата по вопросу — проверить исходящее письмо и результаты по вопросам (их проставляет фоновый
     процесс по зарегистрированному письму).
4. Отчёт в файл — навыки `pdf-report` или `excel-report`; для контроля по исполнителям — навык `og-control`.

В конце — оговорка скрипта (`disclaimer`).

## Правила

- Не пересчитывай сроки «в уме» вместо скрипта и не спорь с `deadline` из RX без причины из результата проверки.
- Особые сроки (установленные законом для отдельных категорий, сокращённые по регламенту) скрипт не знает —
  если пользователь их назвал, учитывай и скажи об этом.
