# Drill-down модалка по колонкам аналитики исходящих

Дата: 2026-06-02

## Проблема / цель

Сейчас на промпт «аналитика по исходящим поручениям» выдаётся: короткая сводка
+ длинные текстовые списки по категориям (со ссылками и `📋`-репортом) + чарт.
Нужно: в ответе показывать **только визуализацию**; при клике по колонке (например
«Просроченные») открывать модальный список поручений со ссылками, статусом, сроком,
ответственным и кнопкой «Отчёт». Вывод отчёта от модели должен падать **в модалку**,
а не в чат.

## Поток данных

1. Промпт → `_direct_rx_response` → `get_action_items_created_by_me`
   (расширяется исполнителем) → `_format_outgoing_action_item_analytics`.
2. Функция возвращает только короткую сводку (`Всего: N`) + маркер
   `[[DIRECTUM_ANALYTICS:{...}]]`. Текстовые секции «В работе / Срок завтра /
   Просроченные» убираются.
3. Каждая колонка (bar) в маркере несёт массив `items`:
   `{id, subject, url, status, deadline, performer}`.
4. Фронт рисует кликабельные колонки; клик → модалка со списком; кнопка «Отчёт»
   дёргает `/api/chat` и рендерит ответ в модалку.

## Форма маркера

```json
{
  "kind": "outgoing_action_items",
  "title": "Аналитика по исходящим поручениям",
  "subtitle": "Всего: 53",
  "charts": [{
    "type": "bar",
    "title": "Распределение по срокам",
    "bars": [
      {"label": "В работе", "value": 41, "tone": "work", "items": [
        {"id": 42, "subject": "…", "url": "…", "status": "InProcess",
         "deadline": "2026-06-10T18:00:00+04:00", "performer": "Иванов И.И."}
      ]},
      {"label": "Срок завтра", "value": 7, "tone": "due-soon", "items": [...]},
      {"label": "Просрочено", "value": 5, "tone": "overdue", "items": [...]}
    ]
  }]
}
```

## Бэкенд

- `AssignmentSummary` → опциональное поле `performer: str | None = None`.
- `assignments.get_action_items_created_by_me` → `$expand` исполнителя.
  Точная навигация (`Performer` / `Assignee` / parts) **верифицируется на живом
  стенде**; при отсутствии — фолбэк `None`, в UI «—».
- `_format_outgoing_action_item_analytics` → убрать текстовые секции, встроить
  `items` (id, subject, url, status, deadline, performer) в каждый bar.

## Фронтенд

- `renderBarChart`: если у bar есть непустой `items` — колонка кликабельна
  (cursor pointer, role=button, ховер-подсветка, клавиатурная доступность).
- Новый `<dialog>` (по образцу `#prompt-dialog`): заголовок = категория; список
  поручений — тема-ссылка (url, target=_blank), статус, срок (формат ru), ответственный;
  кнопка «Отчёт» на каждый пункт.
- Кнопка «Отчёт» → `fetch('/api/chat', {message:"отчёт поручение #id", history:[]})`,
  ответ рендерится в модалку под поручением. В `chatHistory` не пишем, чат не трогаем.
- CSS — только токены `var(--…)`, без hex.

## Область (вне рамок)

- Чарт исполнительской дисциплины остаётся некликабельным (только агрегаты).
- Логика отчёта (`_direct_action_item_report_response`) переиспользуется без изменений.

## Тестирование (TDD)

- Unit: `_format_outgoing_action_item_analytics` — нет текстовых секций (только
  сводка + маркер), bars несут items с нужными полями, правильная категоризация.
- Unit: `get_action_items_created_by_me` возвращает `performer` (мок с expand).
- Live Playwright: клик по колонке → модалка со списком; клик «Отчёт» → текст в модалке.
