# Как создать навык и агента: инструкция

Для кого: аналитики и разработчики, которые добавляют новые сценарии ИИ-ассистента для Directum RX (mcpOGV,
LibreChat / Cowork).

**Адреса в инструкции — заглушки.** Подставьте свои папки:

| Заглушка | Что это |
|---|---|
| `<ПАПКА_ШАБЛОНОВ>` | Папка с этой инструкцией и шаблонами (`skill-template/`, `agent-prompt-template.md`, `test_skill_template.py`) |
| `<ПАПКА_НАВЫКОВ>` | Исходники навыков: по папке на навык и скрипт упаковки `package_skills.py` |
| `<ПАПКА_АРХИВОВ>` | Готовые архивы навыков для загрузки в платформу и их перечень `README.md` |
| `<ПАПКА_ПРОМПТОВ>` | Системные промпты агентов |
| `<ПАПКА_ТЕСТОВ>` | Тесты скриптов навыков |


## 1. Три кирпичика — что есть что

Проще всего представить ассистента как нового сотрудника:

| Кирпичик             | На что похоже                       | Что это технически                                                                        |
| -------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------- |
| **Агент**            | Сотрудник с должностной инструкцией | Системный промпт: роль, правила, какие инструменты и навыки использовать                  |
| **Тул** (инструмент) | Доступ сотрудника к RX              | Функция MCP-сервера mcpOGV: найти, прочитать, создать в Directum RX                       |
| **Навык**            | Методичка + калькулятор             | Папка с `SKILL.md` (порядок работы) и, при необходимости, скриптом, который считает точно |

Зачем делить: модель хорошо понимает текст, но ошибается в подсчётах и забывает длинные правила. Поэтому:
- данные — **только из тулов** (модель не должна ничего придумывать);
- точные расчёты и проверки — **в скрипте навыка** (сроки, просрочки, сравнение, сверка);
- порядок работы и предметные правила — **в SKILL.md**;
- роль, границы и «когда что включать» — **в промпте агента**.
## 2. Что делать: тул, навык или агент?

| Ситуация                                                                       | Что делать                                                        |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Нужных данных из RX нет ни в одном туле                                        | **Новый тул** в mcpOGV (это разработка сервера, отдельная задача) |
| Данные есть, но задачу каждый раз решают по-разному или с ошибками в подсчётах | **Новый навык** (со скриптом, если нужно считать)                 |
| Типовую задачу нужно делать по шагам и предметным правилам, считать нечего     | **Навык без скрипта** — только `SKILL.md`                         |
| Появилась новая роль пользователя со своим набором задач (канцелярия, кадры)   | **Новый агент** с набором навыков                                 |
| Задача нужна всем ролям (отчёт, файл, таблица)                                 | **Общий навык**, подключить ко всем агентам                       |

Правило: сначала проверить, нельзя ли расширить существующий навык. Два похожих навыка путают модель.

## 3. Как создать навык — по шагам

### Шаг 1. Опишите задачу словами пользователя

Запишите 3–5 фраз, как пользователь будет просить: «что горит по обращениям», «можно ли продлить срок». Зачем: по этим
фразам модель решает, включать ли навык. Если фраз не придумать — навык, скорее всего, не нужен.

### Шаг 2. Найдите данные

Какими тулами MCP получить всё нужное? Проверьте в чате с агентом или в описании тулов. Если данных нет — необходимо разрабатывать новый тул.

### Шаг 3. Скопируйте шаблон

```bash
cp -r <ПАПКА_ШАБЛОНОВ>/skill-template <ПАПКА_НАВЫКОВ>/my-skill
```

Имя папки = имя навыка: строчные латинские буквы, цифры и дефисы (`og-terms`, `xlsx-read`). Префикс по области:
`og-` обращения, `pa-` правовой отдел, `kd-` контроль, без префикса — общий навык.

### Шаг 4. Заполните заголовок SKILL.md — самое важное

```yaml
---
name: my-skill
description: Что делает и какой результат. Используй, когда просят «фраза 1», «фраза 2», «фраза 3».
---
```

- `name` — совпадает с именем папки.
- `description` — до 1024 символов. Модель видит **только его**, пока не решит открыть навык. Поэтому: что делает +
  какой результат + живые фразы пользователя.

Плохо: `description: Навык для работы с поручениями.` — непонятно, когда включать.
Хорошо: `description: Готовность поручения к снятию с контроля — проверка по досье… Используй, когда спрашивают «можно
снимать с контроля», «что мешает закрыть».`

### Шаг 5. Напишите тело SKILL.md

Разделы шаблона и зачем они:

| Раздел | Зачем |
|---|---|
| Когда использовать | Чтобы навык не включался «не туда» — укажите и когда **не** использовать |
| Данные | Какие тулы и в каком порядке — модель не будет искать наугад |
| Скрипт | Как вызвать, что вернёт, коды выхода — модель сама исправит ошибку при коде 2 |
| Как отвечать | Единая форма ответа: сначала вывод, потом детали со ссылками |
| Правила | Чего нельзя: выдумывать, выводить персональные данные, принимать решение за человека |

Пишите коротко и конкретно, как инструкцию новому сотруднику. Без фигурных скобок — LibreChat их ломает.

### Шаг 6. Скрипт (если нужно считать или проверять)

Шаблон `scripts/skill_script.py` уже умеет главное — оставьте это, замените только логику в `check()`:
- читает ответ тула **как есть** (файл или `-` из stdin) — модели не нужно ничего переделывать;
- выдаёт JSON (для дальнейшей работы) или `md` (для ответа пользователю);
- коды выхода: **0** успех, **2** ошибка входных данных (понятное сообщение — модель поправит вызов), **1** сбой;
- только стандартная библиотека Python; если нужен пакет — впишите его в `requirements.txt`.

Положите в `examples/` реальный (обезличенный) ответ тула — по нему проверяют навык.

Скопируйте `test_skill_template.py` в `<ПАПКА_ТЕСТОВ>`, задайте в `SKILL_DIR` абсолютный путь к папке навыка
или путь относительно папки теста, затем замените `SCRIPT_NAME` и проверки под свою логику. Запустите
`python -m pytest <ПАПКА_ТЕСТОВ>/test_<имя_скрипта>.py -q` до упаковки.

### Шаг 7. Упакуйте

```bash
python <ПАПКА_НАВЫКОВ>/package_skills.py my-skill
cp <ПАПКА_НАВЫКОВ>/dist/my-skill.zip <ПАПКА_НАВЫКОВ>/dist/my-skill.skill <ПАПКА_АРХИВОВ>/
```

Упаковщик сам проверит заголовок (`name`, `description`, длину) и размер архива. Архив загружают в LibreChat / Cowork.

### Шаг 8. Подключите и опишите

1. Добавьте навык в промпт агента — в «Карту задач и навыков» и в шапку «Агенту нужны».
2. В LibreChat: загрузить архив → подключить к агенту → **начать новый чат** (старый чат навык не увидит).

## 4. Как создать агента — по шагам

### Шаг 1. Роль и задачи

Кто пользователь (контролёр, регистратор, юрист) и 5–10 его типовых задач его словами. Зачем: из этого списка
получатся «Карта задач» и «Типовые сценарии» промпта.

### Шаг 2. Состав

Для каждой задачи: какие тулы и какой навык. Задача без навыка — нормально, если хватает тула. Задача без тула —
сначала нужен тул.

### Шаг 3. Скопируйте шаблон

```bash
cp <ПАПКА_ШАБЛОНОВ>/agent-prompt-template.md <ПАПКА_ПРОМПТОВ>/my-agent.md
```

### Шаг 4. Заполните разделы

| Раздел | Зачем | Совет |
|---|---|---|
| Роль (первый абзац) | Модель понимает, кто она и для кого | 2–3 предложения, без общих слов |
| Главные правила | Границы: только факты, ссылки, права RX | Общие правила оставьте как в шаблоне, добавьте 1–2 предметных |
| Чья это учётная запись | Служебная учётка искажает «мои» данные | Не удалять |
| Карта задач и навыков | По запросу — навык и тулы | Таблица — модель читает её лучше текста |
| Инструменты | Только нужные тулы, с ключевыми полями | Меньше тулов — меньше ошибок выбора |
| Типовые сценарии | Готовые цепочки вызовов | 4–8 сценариев из шага 1 |
| Создание в RX | Запись только через предпросмотр и «да» | Не удалять, если у агента есть тулы записи |
| Форматы, Когда уточнять | Единый вид ответов | Как в шаблоне |

Всё между «НАЧАЛО ПРОМПТА» и «КОНЕЦ ПРОМПТА» — текст для модели; ниже — заметки для настройки (их в платформу не
копируют).

### Шаг 5. Настройте в LibreChat / Cowork

1. Создать агента, вставить текст промпта в «Инструкции».
2. Подключить MCP-сервер mcpOGV и отметить тулы из раздела «Инструменты».
3. Подключить навыки, включить выполнение кода (если есть навыки со скриптами).
4. Если агент — субагент главного: добавить его главному в Subagents и расшарить пользователям.

### Шаг 6. Проверьте на живых вопросах

Задайте агенту каждую фразу из шага 1. Смотрите: тот ли навык включился, нет ли выдуманных цифр, есть ли ссылки.
Что не так — правьте промпт или `description` навыка, а не отвечайте модели «в чате».

### Шаг 7. Опишите

Строка в таблице «Агенты: что подключить» и юзкейсы в `<ПАПКА_АРХИВОВ>/README.md`.

## 5. Частые ошибки

| Ошибка | Чем плохо | Как правильно |
|---|---|---|
| Расплывчатый `description` | Навык не включается или включается не к месту | Что делает + фразы пользователя |
| Модель считает «в уме» | Ошибки в сроках и количествах | Расчёт — в скрипте, в SKILL.md: «числа только из вывода скрипта» |
| Фигурные скобки в промпте или SKILL.md | LibreChat ломает текст | Писать без них |
| `name` не совпадает с папкой | Упаковщик не соберёт архив | Одинаковые имена |
| Проверка в старом чате | Новый навык или тул не виден | Всегда новый чат |
| Персональные данные в примерах и выводе | Утечка ПДн | Обезличенные примеры, в выводе — без контактов граждан |
| Агенту даны все тулы «на всякий случай» | Модель путается в выборе | Только нужные для его задач |
| Запись в RX без подтверждения | Создаются лишние документы | Предпросмотр → «да» → `confirm_token` (исключение — только оговорённые, как `doc-version`) |

## 6. Чек-лист перед выпуском

Навык:
- [ ] `name` = имя папки; `description` — что делает + фразы пользователя, до 1024 символов
- [ ] В SKILL.md: когда использовать, данные (тулы), как отвечать, правила
- [ ] Скрипт: коды 0 / 2 / 1, читает ответ тула как есть; пример в `examples/`
- [ ] Тесты в `<ПАПКА_ТЕСТОВ>` проходят: `python -m pytest <ПАПКА_ТЕСТОВ> -q`
- [ ] Архив собран `package_skills.py` и скопирован в `<ПАПКА_АРХИВОВ>`
- [ ] Навык добавлен в промпт агента и в оба README

Агент:
- [ ] Промпт по шаблону, без фигурных скобок
- [ ] Карта задач: у каждой задачи есть тул и (если нужно) навык
- [ ] Настроен в платформе: тулы отмечены, навыки подключены, выполнение кода включено
- [ ] Проверен на 5–10 живых вопросах в новом чате
- [ ] Строка в «Агенты: что подключить» и юзкейсы в `<ПАПКА_АРХИВОВ>/README.md`
