# Handoff: обновление mcpOGV на дев-стенде 68 до текущей ветки

Для новой агентной сессии, которая работает **на машине дев-стенда**. Читать целиком перед началом. Общение с
пользователем — по-русски. Секреты — только плейсхолдеры, креды — только в переменных окружения или в файлах вне
репозитория (`run.ps1`, `MCP_ACCOUNTS_FILE`). `.env` в репозитории не трогать.

## 1. Цель

На дев-стенде работает старая версия mcpOGV. Последние правки ветки `feature/mcp-ogv` там ещё не приняты. Нужно
обновить сервер до коммита **`7221a55`** или новее, донастроить окружение и проверить, что:

- старое поведение не сломалось: учётки, ключ, тулы;
- новые возможности работают: личный режим, профили учёток, этап 0 для процессов, тулы классификатора.

**Стенд 68:**
- RX — `https://governmentgenai.directum360.ru/` (172.16.104.68);
- сервис интеграции — `https://governmentgenai.directum360.ru/Integration/odata`;
- mcpOGV — порт 8010, снаружи хоста закрыт;
- сервис классификатора Class OG — порт 8020, после их деплоя.

Порядок выбора учётки RX на каждый запрос:
1. `X-Directum-Login` + `X-Directum-Password`;
2. `Authorization: Basic base64(логин:пароль)`;
3. `X-MCP-Account: <профиль>` из `MCP_ACCOUNTS_FILE` (неизвестный профиль — ошибка, а не переход на служебную);
4. служебная учётка `DIRECTUM_AUTH_TOKEN` при `MCP_ALLOW_ENV_CREDENTIALS=true`;
5. иначе — ошибка «Укажите логин и пароль».

## 4. Порядок работ

### 4.1. Разведка (только чтение)

1. Найти, откуда запускается сервер:
   - запуск — `C:\Users\vm-operator\mcp-ogv-run\start-mcp.bat` (меню выбора учётки), рядом `run.ps1` с переменными;
   - путь к репозиторию — в `start-mcp.bat` / `run.ps1` (`cd …`, путь к `python`). **Содержимое `run.ps1` пользователю
     в чат не выводить** — там пароли. Показать только имена переменных.
2. В каталоге репозитория:

   ```powershell
   git status
   git branch --show-current
   git log --oneline -1
   ```

   Зафиксировать текущий коммит — это точка отката.
3. Кто слушает 8010 и 8020:

   ```powershell
   Get-NetTCPConnection -State Listen -LocalPort 8010,8020 -ErrorAction SilentlyContinue | Select LocalAddress,LocalPort,OwningProcess
   ```

4. Работает ли сейчас сервер: `curl.exe -s http://127.0.0.1:8010/health` → `{"status":"ok","server":"mcpOGV"}`.

### 4.2. Согласовать с пользователем

Перед остановкой сервера сказать пользователю:
- текущий коммит;
- какие агенты Cowork / LibreChat подключены (они потеряют связь на время перезапуска, 1–2 минуты);
- какие настройки будут добавлены.

Без явного «да» сервер не останавливать.

### 4.3. Обновление кода

```powershell
git fetch origin
git switch feature/mcp-ogv
git pull --ff-only origin feature/mcp-ogv
git log --oneline -1          # 7221a55 или новее
uv pip install --python .venv\Scripts\python.exe -e ".[dev]"   # если uv нет: .venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest tests/ --ignore=tests/e2e -q -p no:cacheprovider   # ожидаемо ~1118 passed
```

- Локальные изменения в репозитории стенда — не затирать: показать пользователю `git status` и решить с ним.
- `pull --ff-only` не прошёл — не делать `reset --hard`, разобраться.

### 4.4. Настройки окружения (`run.ps1`)

Добавить (или проверить) переменные. `run.ps1` правит пользователь или агент с его явного согласия. Значения
секретов не печатать.

| Переменная | Значение | Зачем |
|---|---|---|
| `MCP_WRITE_PROCESS_TASK_TYPES` | `ISimpleProcessTasks` (для теста на простой задаче — `ISimpleProcessTasks,ISimpleTasks`) | К каким задачам агент прикладывает документы по `task_id` |
| `MCP_ACCOUNTS_FILE` | путь к JSON рядом с `run.ps1`, например `C:\Users\vm-operator\mcp-ogv-run\accounts.json` | Профили учёток для `X-MCP-Account` |
| `MCP_CLASSIFIER_URL` | `http://127.0.0.1:8020` (сервис на той же машине) или `http://172.16.104.68:8020`; **пусто, пока Class OG не задеплоили** — тогда тулов `classifier_*` не будет | Тулы классификатора |
| `MCP_CLASSIFIER_TIMEOUT_SECONDS` | `15` (если на стенде модель Qwen3 на слабом CPU — `30`) | Таймаут сервиса классификатора |
| `MCP_ALLOWED_HOSTS` | проверить, что есть `127.0.0.1:8010` и хост, по которому ходит Cowork | Иначе запросы с этим Host отклоняются транспортом MCP (защита от DNS rebinding) |

Уже должны быть: `DIRECTUM_BASE_URL`, `MCP_OGV_KEY`, `MCP_UTC_OFFSET=+04:00`, `MCP_WRITE_ENABLED`,
`MCP_WRITE_AUDIT_PATH`, при служебной учётке — `MCP_ALLOW_ENV_CREDENTIALS=true` и `DIRECTUM_AUTH_TOKEN`.

Файл профилей, только вне репозитория:

```json
{"nadya": {"login": "<логин RX>", "password": "<пароль RX>"}}
```

Имена профилей — латиница, цифры, `_`, `-`.

### 4.5. Перезапуск и проверки

Перезапустить через `start-mcp.bat`, как раньше. Проверять скриптом-клиентом MCP с машины стенда, без модели. Пример
клиента — `docs/HANDOFF-2026-11-process-on-behalf-stage0.md`, раздел 5.2. Если в окружении задан `HTTP_PROXY`,
для 127.0.0.1 ходить мимо прокси (`trust_env=False` / `curl --noproxy '*'`).

| # | Проверка | Ожидание |
|---|---|---|
| 1 | `GET /health` | `{"status":"ok","server":"mcpOGV"}` |
| 2 | `POST /mcp` без `X-MCP-Key` и с неверным | 401 |
| 3 | `tools/list` с ключом | Прежние тулы + `get_document_relations`, `download_chunk`, `begin_upload…`; `classifier_*` — только при заданном `MCP_CLASSIFIER_URL`; тулы записи — только при `MCP_WRITE_ENABLED=true` |
| 4 | `get_current_user` без личных заголовков | Служебная учётка, `service_account=true` (если включена) |
| 5 | `get_current_user` с `X-Directum-Login/Password` тестового пользователя | Этот пользователь |
| 6 | `get_current_user` с `Authorization: Basic base64(логин:пароль)` | Этот пользователь |
| 7 | `get_current_user` с `X-MCP-Account: nadya` | Пользователь профиля; `X-MCP-Account: nosuch` — ошибка «Профиль … не настроен» |
| 8 | Классификатор (если задеплоен): `classifier_search` «выплаты участникам боевых действий» | 50 рубрик, `0004.0015.0158.0974` в выдаче (у Class OG — 2-е место); `classifier_get` этого кода — `exists: true`; пустой запрос — «Пустой запрос: …» |
| 9 | Этап 0, **только с явного разрешения на запись**: предпросмотр `create_document` с `task_id` задачи процесса в работе, без `on_behalf_of` | «Подготовил» = автор задачи; чужой `on_behalf_of` / завершённая задача — понятные отказы (это предпросмотры, ничего не создаётся) |

Создание документов на стенде (`confirm_token`) — только если пользователь попросит и назовёт задачу. Проверка
доступа: личная учётка → автор документа — пользователь, он его видит. Под служебной учёткой — не видит. Это ожидаемо,
см. раздел 6 спецификации.

### 4.6. Откат

Если что-то не работает и быстро не чинится:
1. `git switch --detach <коммит из 4.1>`;
2. убрать новые переменные из `run.ps1` (старые версии их просто игнорируют, можно оставить);
3. перезапуск, проверка `/health`.

Пользователю — что не заработало, с текстом ошибки из `mcp_server.log` без кредов.

  - какие переменные добавлены (без значений секретов);

  `TOP_K_CANDIDATES=50`, иначе поиск отдаст не больше 10 кандидатов — это их зона, сами не правим.

## 6. Настройка агентов в Cowork (после деплоя, по желанию пользователя)

Вариант 1 спецификации — агент работает под учёткой пользователя:
- **Личные переменные:** MCP-подключение с заголовками `X-Directum-Login: '{{DRX_LOGIN}}'` /
  `X-Directum-Password: '{{DRX_PASSWORD}}'`; пользователь Cowork вводит свои креды RX.
- **Профиль:** отдельное подключение `mcpOGV-nadya` с `X-MCP-Account: 'nadya'` (см. `librechat.example.yaml`),
  подключить его к агенту этого пользователя.

После изменения тулов в Cowork / LibreChat — переинициализировать MCP-сервер, отметить новые тулы у агента, начать
новый чат.

## 7. Правила

- **Секреты и файлы:**
  - не создавать и не редактировать `.env` репозитория;
  - пароли и токены не печатать в чат и логи, не коммитить;
  - `run.ps1` и файл профилей — вне git.
- **Git:**
  - на стенде ничего не коммитить и не пушить;
  - ветки и PR — только с согласия пользователя.
- **Записи в RX** — только с явного разрешения на конкретное действие. Тестовые документы удаляет пользователь, агент
  не удаляет.
- **Тестовые документы со стенда:** письма 16931 и 16932 в задаче 86316 (тесты 01.11) — напомнить пользователю удалить,
  если ещё не удалены.
- **Никогда не вызывать:**
  - `CoreEntities.*`;
  - `Company.CreateLogin` / `SetLoginPassword`;
  - `Shell.AddUserToGroup` / `RemoveUserFromGroup`;
  - `Docflow.GrantAccessRights*` без разрешения;
  - `SmartProcessing.ElasticsearchReindex`;
  - `Company.*TransferSubstitutedAccessRights`.
- **Зоны с сессией «Class OG».** Контракт их агента: `get_document`, `get_document_text`, `get_citizen_request_status`,
  `og-repeat`, `classifier_search`, `classifier_get`. Его не меняем без сообщения им. Их сервис и `.env` не трогаем.
- **HR Pro** (ветка `feature/mcp-hrpro`) **на паузе** — не трогать.
